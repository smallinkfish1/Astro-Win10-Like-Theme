# 如何在本地发布一篇文章

这篇文章带你走一遍完整流程：**写一个 `.md` 文件，然后它就会出现在桌面上。**

## 第一步：新建文件

在 `src/content/blog/` 目录下新建一个 `.md` 文件。

文件名会变成你的文章地址，所以**用英文小写 + 连字符**：

```text
src/content/blog/my-first-post.md
     ↓ 对应地址
/posts/my-first-post/
```

> ⚠️ 文件名里**不要用中文和空格**。它们会被转义成一长串 `%E4%B8%AD...`，
> 地址又长又难分享。文件名叫 `my-first-post`，标题写中文，这样最好。

## 第二步：写 frontmatter

文件**开头**必须是两行 `---` 包起来的一段，这叫 frontmatter。它是文章的元信息：

```markdown
---
title: 我的第一篇文章
description: 一句话说清这篇在讲什么，会用在列表页和搜索结果里。
pubDate: 2026-10-06
category: 随笔
tags: ["入门", "记录"]
---

正文从这里开始。
```

各字段的含义：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✅ | 文章标题 |
| `description` | | 摘要，列表页和 SEO 都用它 |
| `pubDate` | ✅ | 发布日期 |
| `category` | | 分类。支持 `技术/Hexo` 这种斜杠层级 |
| `tags` | | 标签，数组写法 |
| `draft` | | 见下面「写草稿」一节 |
| `accent` | | 可选，卡片左侧的色条颜色 |

> ⚠️ 这些字段有**类型校验**。写错类型或者漏掉必填项，`npm run build` 会直接报错并告诉你是哪个文件 —— 不会等到页面上出现一个 `undefined`。

## 第三步：写正文

正文就是普通的 Markdown，支持：

- **粗体**、*斜体*、`行内代码`
- 列表、表格、引用块
- 代码块（带语法高亮）
- LaTeX 数学公式

代码块这么写：

````markdown
```ts
export function add(a: number, b: number) {
  return a + b;
}
```
````

数学公式用 `$` 包起来：

```markdown
行内公式：$E = mc^2$

块级公式：

$$
\int_0^1 x^2 \,\mathrm{d}x = \frac{1}{3}
$$
```

## 第四步：看效果

如果开发服务器开着（`npm run dev`），保存文件后页面会**自动刷新**。

打开桌面上的「此电脑」，你的新文章就会出现在对应的分类文件夹里。双击它就能打开阅读窗口。

## 写草稿

不想现在发布，就在 frontmatter 里加一行：

```markdown
---
title: 还没写完的东西
pubDate: 2026-10-06
draft: true
---
```

`draft: true` 的文章：

- ❌ **不会**出现在 `/posts`、分类页、标签页、归档页
- ❌ **不会**进 RSS 和搜索索引
- ✅ **会**出现在桌面的「回收站」里

> 不写 `draft` 这一行就默认是 `false`，也就是正式文章。所以**发布一篇文章 = 删掉 `draft: true` 那一行**。

## 常见问题

**文章没出现？**

按顺序检查这三条：

1. 文件是不是放在 `src/content/blog/` 下（不是别的地方）
2. frontmatter 的两行 `---` 有没有写全（只有开头一行是常见的错）
3. 有没有写 `draft: true`

**构建报错说什么字段缺失？**

翻到报错信息里的文件路径，对照上面那张字段表检查一遍。最常见的是 `pubDate` 写成了 `date`。

**能不能改文件名？**

能，但**改完地址就变了**。如果文章已经被分享出去，旧链接会 404。所以**发布之后就尽量别再改文件名**。
